# اسکنر IPA + ربات تلگرام — سیب‌استار (نسخه ۹)

[English summary below](#english-summary)

ربات تلگرام برای اسکن امنیت و حریم خصوصی فایل‌های `.ipa` (برنامه و بازی آیفون).
یک فایل IPA برام بفرستید، یا لینک مستقیم دانلود یک فایل `.ipa` بدهید؛ ربات آن را
اسکن می‌کند و به فارسی گزارش می‌دهد: خلاصه کوتاه در چت + **چهار فایل**:
**کارت تصویری خلاصه (PNG)** + **گزارش مشتری (`.md`، به زبان ساده — برای ارسال
به کاربر)** + **گزارش فنی کامل (`.md`، فقط برای خودت)** + داده‌ی فنی (`‌.json`).

**نسخه ۹ با MTProto کار می‌کند (Telethon، مثل لینک‌یار) و فایل تا ۲ گیگابایت را
می‌گیرد** — نسخه ۲ با Bot API فقط تا ۲۰ مگابایت می‌گرفت.

## نسخه ۹ — نسخه‌ی آنلاک در این فروشگاه عادی است؛ حکم درباره‌ی امنیت داده است

در فروشگاه سیب‌استار نسخه‌های مادشده/آنلاک («Premium Unlocked»، «Patched») خودِ
محصول‌اند — مشتری عمداً همان را می‌خرد. پس نسخه‌ی آنلاک به‌تنهایی نه امتیاز
می‌گیرد و نه هشدار:

- **امتیاز فقط برای خطر واقعی است:** سرور ناشناسِ بخش اضافه ۱۵ امتیاز، نقطه‌ی
  آپلود همراه آن سرور ۷ امتیاز، دسترسی به کی‌چین در بخش اضافه‌ای که سرور دارد
  ۳ امتیاز. برنامه‌ی مادشده بدون سرور دقیقاً مثل نسخه‌ی تمیز امتیاز می‌گیرد
  (TamperedCollage ‏۱۹ = CleanCollage ‏۱۹؛ Mercury ‏۰ = WeatherNow ‏۰). برنامه‌ی
  واقعاً خطرناک هنوز بالا می‌گیرد (DangerousCollage ‏۷۳ = اصلی ۴۸ + ارسال داده ۲۵).
- **کلمه‌ی «دستکاری» از همه‌ی خروجی‌های مشتری‌محور حذف شد** (کارت، خلاصه‌ی
  چت، حکم‌ها و پاسخ‌ها). واقعیت آنلاک بودن یک بار، خنثی، گفته می‌شود:
  «نسخه آنلاک شده؟» با برچسب خاکستری/آبی «بله» — هرگز قرمز، هرگز هشدار.
  حکم درباره‌ی امنیت داده است: بدون مدرک ارسال داده «مشکلی پیدا نشد؛ با خیال
  راحت استفاده کنید»؛ با تأیید ارسال داده «این نسخه اطلاعات شما را به سروری
  ناشناس می‌فرستد؛ نصب نکنید».
- **دو گزارش جدا:** گزارش مشتری (`.md`، فقط اسم برنامه، یک خط حکم، چهار سؤال
  با جواب‌های قاطع و چند جمله‌ی ساده — بدون اصطلاح فنی، بدون فهرست دامنه، بدون
  تفکیک امتیاز) برای ارسال به کاربر؛ گزارش فنی کامل (`.md`، تحلیل هر dylib با
  دامنه‌ها، همه‌ی یافته‌ها با شدت و مدرک، فهرست کامل دامنه/URL، هش‌ها،
  entitlements، تفکیک ریسک با امتیاز) فقط برای خودت. فایل JSON هم جزئیات فنی
  کامل را دارد.
- کالیبراسیون نسخه ۹: CleanCollage ‏۱۹، TamperedCollage ‏۱۹، DangerousCollage ‏۷۳،
  WeatherNow ‏۰، WeatherNowTampered ‏۰، TestGame ‏۷۹ (اصلی ۶۱ + ارسال داده ۱۸)،
  CleanNotes ‏۵، FreeGame ‏۲۵.

## نسخه ۸ — درس Mercury و Crsel: فقط همان چیزی را بپرس و امتیاز بده که واقعی است

نسخه ۷ روی دو IPA واقعی (Mercury Weather و Crsel، هر دو نسخه‌ی مادشده) تست شد و
باز هم برای هیچ ترسناک بود — این بار نه از «توانایی»، که از سؤال‌های بی‌جا و
مثبت‌های کاذب:

- **سؤال عکس برای برنامه‌ای که عکس نمی‌خواند:** Mercury فقط اجازه‌ی «ذخیره»
  (add-only) دارد — اسکرین‌شات ذخیره می‌کند، عکس‌های شما را نمی‌خواند — ولی
  نسخه ۷ سه سؤال «عکس‌ها فرستاده می‌شوند؟ / کسی عکس‌ها را می‌بیند؟ /
  اطلاعات عکس جمع می‌شود؟» را می‌پرسید. نسخه ۸ سؤال عکس را **فقط وقتی
  می‌پرسد که برنامه واقعاً عکس بخواند** (دسترسی خواندن یا استفاده‌ی مستقیم
  از PhotoKit)؛ وگرنه یک خط ساده می‌گوید «این برنامه عکس‌های شما را
  نمی‌خواند؛ فقط می‌تواند اسکرین‌شات ذخیره کند».
- **امتیاز به برنامه برای کار خودش:** موقعیت در برنامه‌ی هواشناسی (+۵)،
  `dlopen` و سنسور حرکتی در باینری اصلی. نسخه ۸ **امتیاز متناسب با کار
  برنامه** می‌دهد: API/دسترسی‌ای که کار اصلی برنامه است ۰ امتیاز می‌گیرد
  («موردنیاز برای کار اصلی برنامه»)، و الگوهای عمومی باینری اصلی
  (pasteboard، keychain، sysctl، IOKit، اطلاعات اپراتور، اینترفیس‌های
  شبکه، dyld، ضبط صدا، جستجوی کلاس در ران‌تایم) فقط اطلاعات‌اند — فقط
  داخل dylib تزریقی امتیاز می‌گیرند.
- **مثبت‌های کاذب Crsel (اصل برنامه ۴۹/۱۰۰ بود):** آدرس‌های http «ناامن»
  که در واقع بررسی اعتبار گواهی (CRL/OCSP)، متن مجوز فونت، لینک
  کوتاه‌شده، یا رشته‌های به‌هم‌چسبیده‌ی خراب بودند — حالا اعتبارسنجی
  می‌شوند و فقط آدرس http واقعی شمرده می‌شود. `FacebookClientToken`
  توکن عمومی فیس‌بوک است، نه رمز سخت‌کدشده. entitlement
  `extended-virtual-addressing` برای ویرایشگر عکس/ویدیو عادی است (۰
  امتیاز). هر ترکر **یک بار** شمرده می‌شود (دامنه‌ی ترکر وقتی SDK آن
  قبلاً شمرده شده، دوباره امتیاز نمی‌گیرد). Snap Kit و TikTok SDK
  ابزار اشتراک/ورودند، نه ترکر.
- **کارت حداقلی برای مشتری غیرفنی:** فقط نام برنامه + نسخه، **یک**
  امتیاز با یک خط ساده («هرچه عدد کمتر باشد، بهتر است»)، **یک** جمله‌ی
  حکم، و حداکثر ۴ سؤال کوتاه با برچسب یک‌کلمه‌ای («نه» / «دستکاری شده» /
  «سالم»). بدون ردیف آمار، بدون عددهای ترسناک («۴۱ اتصال بدون محافظت»)،
  بدون یادداشت فنی، بدون تکرار، بدون هیچ اصطلاحی. پیام دستکاری دقیقاً
  یک بار می‌آید. جزئیات کامل فقط در گزارش `.md` است (برای ارفان).
- **کالیبراسیون سه‌طرفه** (`test/make_calibration_ipa.py`): برنامه‌ی
  کلاژ سالم با همان سوپ Crsel **۱۹/۱۰۰ — کم**؛ همان برنامه با دو dylib
  تزریقی **۴۴/۱۰۰** (اصل ۱۹ بدون تغییر + توئیک ۲۵) — نه ۷۴؛ برنامه‌ی
  خطرناک (توئیک با سرور ناشناخته‌ی خودش + نقطه‌ی آپلود عکس واقعی)
  **۷۳/۱۰۰ — بالا** و جواب سؤال‌های عکس **بله** با سرور به‌عنوان مدرک.
  این تنها حالتی است که «بله» درست است: توئیک هم کانال دارد (سرور
  خودش) و هم نقطه‌ی آپلود.
- **Mercury زیر نسخه ۸: ۲۵/۱۰۰ — متوسط** (اصل ۰ + توئیک ۲۵)؛ **Crsel
  زیر نسخه ۸: حدود ۴۴ تا ۵۰/۱۰۰ — متوسط** (اصل حدود ۱۹ تا ۲۵ + توئیک
  ۲۵) — عدد دقیق Crsel بدون اسکن دوباره‌ی IPA واقعی معلوم نیست، چون
  گزارش فقط ۲۰ آدرس از ۴۱ آدرس http را نشان می‌داد.
- نسخه ۷ (که در README جداگانه نیامده) حکم «توانایی دارد» را کامل
  حذف کرد: وقتی سروری برای فرستادن نیست، جواب قاطع «نه — نمی‌فرسته»
  است، نه «فقط توانایی دارد». نسخه ۸ همان را نگه می‌دارد و سرفصل
  کارت را هم بر اساس **حکم** دستکاری می‌نویسد (یک نشانه = «مشکوک»،
  نه «دستکاری شده است»).

## نسخه ۵ — چه چیزی نسبت به نسخه ۴ بهتر شد؟

نسخه ۴ روی همان IPA واقعی (PDF Hero، نسخه‌ی مادشده، ریسک ۷۷/۱۰۰) تست شد و
باز هم برای هیچ ترسناک بود. مشکل این بود که «توانایی» با «واقعیت» اشتباه
گرفته شده بود: دسترسی به عکس + حرف زدن با چند سرور آنالیتیکس، «بله، عکس‌ها
به سرور می‌روند» گزارش شده بود — در حالی که هیچ‌کدام از آن سرورها (adjust،
Firebase logging، Lokalise، Firebase Realtime Database) سرور آپلود عکس
نیستند. نسخه ۵ این را اصلاح می‌کند:

| بخش | نسخه ۴ | نسخه ۵ |
|---|---|---|
| پاسخ‌های حریم خصوصی | «بله» بر اساس توانایی (دسترسی به عکس + سرور آنالیتیکس = ارسال عکس) | ✅ **حکم سه‌سطحه‌ی مدرک‌محور: «تأیید شد» / «شواهدی نیست» / «فقط توانایی دارد، اثبات نشده»** — هیچ‌وقت بر اساس توانایی به‌تنهایی «بله» گفته نمی‌شود. برای PDF Hero: ارسال عکس «شواهدی نیست»، دیدن عکس توسط توئیک «فقط توانایی دارد» (همان پروسس، دسترسی به keychain/ران‌تایم) و سرور ناشناخته‌ی توئیک پیدا نشد، پس اثبات نشده است. محدودیت تحلیل ایستا یک بار گفته می‌شود، نه در هر سؤال |
| APIهای معمولی iOS | ASIdentifierManager، PhotoKit، Speech «مشکوک» شمرده می‌شدند (+۵ هر کدام) | ✅ **۰ امتیاز، با برچسب «معمولی»** — این APIها در هزاران برنامه‌ی سالم استفاده می‌شوند و دیگر تهدید نیستند. دسترسی‌های موقعیت/مخاطبین/دوربین/میکروفون هم وقتی توضیح استفاده «تبلیغات» می‌گوید و مدرک خروج داده نیست، حداکثر ۱ امتیاز می‌گیرند و به زبان ساده توضیح داده می‌شوند |

| تکرار بخش‌ها | بخش «دستکاری شخص ثالث» دو بار کپی شده بود (یک بار بخش جدا، یک بار داخل پاسخ‌ها) | ✅ هر بخش **یک بار**؛ پاسخ حریم خصوصی برای دستکاری فقط ۲ خط خلاصه + ارجاع به بخش کامل است |
| کارت PNG | حکم‌ها با «بله» ترسناک نشان داده می‌شدند | ✅ بازطراحی: **حکم‌های مدرک‌محور** («تأیید شد» / «شواهدی نیست» / «فقط توانایی دارد»)، بنر دستکاری با «تأیید شد» به‌جای «بله»، تفکیک ریسک اصلی/توئیک؛ رندر دوباره با چشم بررسی شد (کارت پرریسک و کارت تمیز) |
| امتیاز تست | ۸۷/۱۰۰ (اصلی ۶۲، توئیک ۲۵) | ✅ **۸۵/۱۰۰ (اصلی ۶۰، توئیک ۲۵)** — اختلاف فقط حذف امتیاز APIهای معمولی است؛ سقف ۸۷ همان است |

## نسخه ۴ — چه چیزی نسبت به نسخه ۳ بهتر شد؟

### روش‌شناسی و استانداردها

اسکن ایستا نسخه ۶ از روش‌های استاندارد حرفه‌ای یاد گرفته است (فقط روش‌ها را
یاد گرفته‌ایم، متن کپی نشده است):

- **MobSF (Mobile Security Framework)** — اسکن باینری iOS: دسترسی‌ها، گواهی
  امضا، تنظیمات ATS، محافظت‌های باینری (PIE، NX، stack canary، ARC)، رمزهای
  سخت‌کدشده در plist/رشته‌ها، قوانین SAST برای رمزنگاری ضعیف، و فهرست ترکرها؛
  یافته‌ها با شدت و نگاشت CWE/OWASP گزارش می‌شوند.
- **OWASP MASVS / MASTG** — دسته‌های STORAGE، CRYPTO، AUTH، NETWORK، PLATFORM،
  CODE، RESILIENCE و PRIVACY؛ هر یافته به یک کنترل MASVS نگاشت می‌شود و سطح
  اطمینان دارد. OWASP صریحاً می‌گوید ابزار خودکار راهنماست، نه حکم قطعی، و
  خروجی می‌تواند مثبت کاذب و منفی کاذب داشته باشد — گزارش ما هم همین را می‌گوید.
- **بهترین روش‌های تحلیل ایستای IPA** — اول هش فایل، بعد هویت/امضا/entitlements،
  بعد بررسی وضعیت رمزگذاری (cryptid) قبل از هر خواندن عمیق‌تر؛ مقایسه‌ی
  مجوزهای provisioning با ادعاهای entitlement؛ بررسی جداگانه‌ی هر `.appex`
  (هر کدام پروسه و entitlement خودش را دارد)؛ تشخیص خانواده‌ی ران‌تایم از
  فریم‌ورک‌ها.
- **تشخیص توئیک/جیلبریک** — شمارش کتابخانه‌های لودشده با dyld و مقایسه با
  مجموعه‌ی مجاز؛ مسیرهای `/Library/MobileSubstrate/`، Cydia، apt و dylibهای
  تزریقی مثل FridaGadget/CydiaSubstrate.

منابع: [MobSF iOS static analysis](https://deepwiki.com/MobSF/Mobile-Security-Framework-MobSF/5.2-ios-static-analysis) ·
[OWASP MASVS](https://mas.owasp.org/MASVS/) ·
[OWASP MASTG](https://mas.owasp.org/MASTG/) ·
[OWASP MASVS — iOS app security checklist](https://github.com/OWASP/owasp-masvs)

## پاسخ به پنج سؤال حریم خصوصی

گزارش نهایی (`.md`)، خلاصه چت و کارت تصویری مستقیماً به این پنج سؤال جواب می‌دهند
(سؤال دستکاری اول است — مهم‌ترین سؤال کاربر):

0. **آیا این نسخه (توئیک) غیر از شرکت اصلی، توسط شخص ثالث دستکاری شده تا داده
   به خودش برسد؟** — بر اساس dylibهای تزریقی (MobileSubstrate)، بسته‌های `.deb`،
   و دامنه‌ی هر dylib جداگانه. اگر توئیک به سرور ناشناخته‌ای وصل شود، نام سرور
   گفته می‌شود؛ اگر نشود، صریحاً گفته می‌شود و محدودیت تحلیل ایستا (ترافیک واقعی
   زمان اجرا دیده نمی‌شود) هم گفته می‌شود.
1. **آیا برنامه عکس‌ها/فایل‌ها را به سرور یا فضای ابری می‌فرستد؟** — بر اساس دسترسی
   گالری، حالت‌های پس‌زمینه، دامنه‌های شبکه و ATS؛ با لیست سرورهایی که برنامه با آن‌ها
   حرف می‌زند. تحلیل ایستا فقط «توانایی» و «آدرس سرورها» را نشان می‌دهد، نه ترافیک واقعی.
2. **آیا سازنده‌ی ماد یا شخص ثالث می‌تواند عکس‌ها/ویدیوهای کاربر را ببیند یا دریافت کند؟**
   — بر اساس ترکرها، دامنه‌های ترکر، http ناامن، ردیابی مانیفست و الگوهای باینری.
3. **آیا برنامه اطلاعات عکس/فایل کاربر را جمع‌آوری می‌کند؟** — بر اساس نوع داده‌های
   اعلام‌شده در مانیفست، دسترسی‌ها، ترکرها و SDKهای تحلیلی.
4. **حکم نهایی** — این نسخه بررسی شده است؟ چه چیزی تأیید شد و چه چیزی قابل بررسی نیست؟
   (مخصوصاً برای IPAهای رمزگذاری‌شده با FairPlay که تحلیل باینری‌شان ممکن نیست.)

هر جواب یک کلمه‌ی حکم کوتاه، مدارک و «محدودیت صادقانه» دارد — جایی که مدرک نیست،
گزارش صریحاً می‌گوید قابل بررسی نیست، نه اینکه چیزی جعل کند. جواب‌ها قاطع‌اند
(«بله» با مدرک)، نه «ممکن است» همه‌جا؛ حکم نهایی هم آرام است («با احتیاط استفاده
کنید»)، نه ترسناک.

## محدودیت مهم — FairPlay

فایل‌های IPA دانلودشده از اپ‌استور با FairPlay رمزگذاری شده‌اند.
باینری رمزگذاری‌شده را نمی‌شود بدون رمزگشایی خواند؛ اسکنر این را تشخیص می‌دهد
(`cryptid=1`) و بخش «رشته‌های باینری» را **«در دسترس نیست»** اعلام می‌کند،
نه اینکه چیزی را جعل کند — همین قانون برای هر فایل `.dylib` رمزگذاری‌شده هم
اعمال می‌شود (جداگانه گزارش می‌شود، نه اینکه بی‌صدا رد شود). برای تحلیل کامل
باینری، به نسخه‌ی رمزگشایی‌شده نیاز است. این پروژه هیچ راهی برای دور زدن
FairPlay ادعا نمی‌کند و ندارد.

## کارت خلاصه‌ی تصویری (PNG)

بعد از هر اسکن، یک کارت PNG تمیز ساخته می‌شود (`report_card.py` با Pillow):
نام برنامه، Bundle ID، نسخه، امتیاز ریسک ۰ تا ۱۰۰ با رنگ آرام (سبز/کهربایی/قرمز
ملایم — فقط دایره‌ی امتیاز رنگی است، نه کل کارت)، سطح ریسک به فارسی، بنر نرم
دستکاری شخص ثالث، جدا بودن ریسک برنامه‌ی اصلی و توئیک، حکم نهایی به زبان ساده،
پاسخ کوتاه پنج سؤال حریم خصوصی، شمارنده‌ها (دسترسی‌ها، ترکرها، دامنه‌های واقعی،
لینک ناامن، فایل dylib، بسته `.deb`) و مهم‌ترین یافته‌ها. متن فارسی راست‌چین و
با شکل‌دهی درست حروف رندر می‌شود (raqm در Pillow، و در غیاب آن arabic-reshaper
+ python-bidi). کارت هم در تلگرام به‌صورت عکس فرستاده می‌شود. اندازه‌ی کارت
۱۲۰۰×۱۳۲۰ است و رندر آن با چشم در تست بررسی شده است (بدون هم‌پوشانی و بریدگی متن).

## پاک‌سازی — فایل‌ها ذخیره نمی‌شوند

هر IPA دانلودشده و هر گزارش تولیدشده فقط داخل یک پوشه‌ی موقت زندگی می‌کند.
**بلافاصله بعد از اسکن و ارسال گزارش، فایل IPA حذف می‌شود** — و پوشه‌ی موقت
حتی اگر دانلود، اسکن یا ارسال ناموفق باشد هم پاک می‌شود. هیچ IPA یا گزارشی
وارد ریپو نمی‌شود و commit نمی‌شود (`.gitignore` جلوی `*.ipa`، گزارش‌های
`*.json`/`*.md` و فایل‌های `*.session` تلگرام را می‌گیرد). این برای اینکه دیسک
رانر گیت‌هاب اکشنز با فایل‌های ۲ گیگابایتی پر نشود.

## استفاده سریع

```bash
# ۱) اسکنر خط فرمان (فقط استاندارد پایتون)
python3 scanner.py app.ipa --json report.json --report report.md

# ۲) کارت تصویری خلاصه
python3 report_card.py app.ipa --out card.png

# ۳) ربات تلگرام — نسخه ۶ به Telethon نیاز دارد (MTProto، برای ۲ گیگابایت)
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN='توکن-از-BotFather'
export TELEGRAM_API_ID='123456'        # از https://my.telegram.org
export TELEGRAM_API_HASH='...'         # از https://my.telegram.org
export ADMIN_USER_IDS='123456789'      # فقط آیدی عددی تلگرام خودت
python3 bot.py --check-config   # فقط بررسی متغیرها، بدون شبکه
python3 bot.py --check-token    # اتصال و تست توکن
python3 bot.py                  # ربات شروع می‌شود و گوش می‌دهد

# ۴) تست آفلاین (بدون تلگرام، بدون شبکه)
python3 bot.py --selftest test/TestGame.ipa
python3 test/test_bot_offline.py
python3 test/test_scanner_v3.py
```

در تلگرام: فایل `.ipa` را برای ربات بفرستید، یا لینک مستقیم یک فایل `.ipa` بدهید.
حداکثر حجم فایل **۲ گیگابایت** است (محدودیت تلگرام)؛ فایل بزرگ‌تر یا غیر IPA با
پیام فارسی رد می‌شود. ربات **یک پیام پیشرفت** نشان می‌دهد که در ۶ مرحله حرکت
می‌کند (۱/۶ دانلود با درصد، ۲/۶ استخراج، ۳/۶ اسکن باینری، ۴/۶ آنالیز dylib و deb،
۵/۶ ساخت کارت و گزارش، ۶/۶ ارسال و پاک کردن)؛ پیام نهایی با حکم دستکاری و ریسک
شروع می‌شود. دستورها: `/start` و `/help`. فقط ادمین (ADMIN_USER_IDS) می‌تواند
از ربات استفاده کند؛ بقیه با پیام فارسی رد می‌شوند.

## <a name="english-summary"></a>English summary

A Telegram bot + deep IPA scanner for SibStar (Persian iOS App Store), v6.
Send an `.ipa` file or a direct `.ipa` link; it replies in Persian with a risk
score (0–100) summary, a PNG summary card, plus full Markdown/JSON reports.
v6 uses Telethon (MTProto, like LinkYar) so files up to 2 GB work (v2's Bot API
limit was 20 MB). v6 scan adds: SDK/build info, plist security (background
modes, file sharing, Bonjour), per-data-type privacy-manifest risk, 65+
tracker SDKs (incl. static libs), 33 suspicious binary patterns, per-domain
risk, per-entitlement severity, provisioning type/expiry, ATS exception
details, per-framework details, per-dylib analysis (encrypted dylibs reported
as unavailable, never silently skipped), per-finding severity, and five
Picsart-style privacy answers with evidence and honest limits. v6 fixes the
v5 flaws: privacy answers are now exactly 3 short plain-Persian lines each
(answer + evidence + limit), with no raw manifest constants, and keep the
3-level evidence verdicts (confirmed / no-evidence / capability) — capability
alone is never reported as "yes" (a photo permission plus analytics servers
is not proof photos are sent); the report's
first screen shows the verdict, risk, tampering and answers, with details
below, and redundant sections (full findings list, standalone jailbreak
section) were removed; the PNG card is dynamically sized to its content,
shows the unknown tweak server, and has no duplicated verdict row; the
chat summary is short (verdict first, risk, four answers) and errors are
plain Persian with a clear ❌ progress message instead of a stuck stage;
calibration: a clean app scores 5/100 and a realistic ad-supported game
25/100 (trackers 2 points each, manifest lines no longer triple-count
tracking, ATS 6, code cap 15 with secrets scored first, capped findings
grouped into one summary line per category instead of silently hidden).
